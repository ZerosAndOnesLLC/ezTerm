# ezTerm v1.14.1

**Persistent sessions and auto-reconnect, hardened.** v1.14.0 promised you'd reconnect without losing anything. This release makes that hold up on flaky networks, slow servers and older Linux distributions.

## What changed

### Reconnect you can rely on (#185)

- **A drop in the middle of logging in no longer looks like a wrong password.** Before, a Wi-Fi blip during login could open the "fix credentials" dialog and stop reconnecting. Now ezTerm tells a dropped link apart from a server refusing you, retries the dropped link, and stops straight away if the server is turning you down. That keeps fail2ban and account lockouts out of it.
- **You get back into your session, not a bare shell.** If the server is slow to respond right after an outage, ezTerm waits longer for it (10 s instead of 4 s). If it still can't find your tmux or screen session, it tries again rather than leaving you in a plain shell while your work keeps running elsewhere. Hosts that can't use tmux or screen at all still get a normal shell with a notice explaining why.
- **Works on older servers.** Reattaching now works on tmux 1.8 and 1.9 (RHEL/CentOS 7, Debian 8), which don't support the exact-match lookup v1.14.0 relied on.
- **A vanished session is recreated.** If your session ended between the check and the reattach (a server reboot, or someone ended it), you get a fresh one instead of the tab closing with "exit 1".
- **Flaky links still give up.** Drops within a minute of a reconnect count as the same outage, so a link that keeps flapping doesn't retry forever. Turning auto-reconnect off now stops a countdown immediately.

### Fixes

- **The SFTP side pane works again after a reconnect.** Before, it stayed stuck on an error until you closed the tab.
- **The bundled X server (VcXsrv) now closes properly** after a failed connect with X11 forwarding on.
- **Exit codes are shown again**, e.g. "Disconnected (exit 1)".
- **Clearer messages** when tmux or screen can't be used: tool missing, a login shell that isn't POSIX, a server that allows only one session channel, or a broken screen socket directory.
- **A readable error** if you open more than 99 tabs of the same persistent session.

### Website

The site now leads with persistent sessions and auto-reconnect, and has a full guide under **Docs → Features → Persistent sessions & auto-reconnect** (#184).
