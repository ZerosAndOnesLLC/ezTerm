# ezTerm v1.15.0

**Symbolic links in the SFTP pane, and persistent sessions you can rely on.** Linked folders and files now work the way you'd expect. Reconnecting without losing anything holds up on flaky networks, slow servers and older Linux distributions.

## What changed

### Symbolic links in the file browser (#186)

Before, symlinks in the SFTP side pane were treated as plain files: a linked folder couldn't be opened, and deleting one failed. Now:

- **Links to folders work like folders.** Double-click to open, they sort with folders, and you can drop uploads onto them.
- **Links to files download the file they point to**, and show its real size and date.
- **You can see where every link points**, e.g. `current → releases/42`, inline and in the tooltip.
- **Broken links are marked** with a red icon and struck through.
- **Delete removes the link, never its target.** The confirmation says so.
- **Special files** (pipes, sockets, devices, and links to them) are no longer offered for download, since reading one can hang.
- **Works in both SSH and WSL tabs.** WSL listings are also faster now (one process per folder), and handle file names with spaces, newlines or `->` in them correctly.
- **Safer downloads.** A file name sent by the server can no longer place a download outside the folder you picked.

### Reconnect you can rely on (#185)

v1.14.0 introduced persistent tmux/screen sessions and auto-reconnect. This release hardens them:

- **A drop in the middle of logging in no longer looks like a wrong password.** ezTerm tells a dropped link apart from a server turning you away: it retries the first and stops at once on the second, so fail2ban and account lockouts stay out of it.
- **You land back in your session, not a bare shell.** ezTerm waits longer for a slow server right after an outage. If it still can't find your session, it tries again instead of stranding your work. Hosts that can't run tmux or screen still get a normal shell, with a notice saying why.
- **Works on older servers**, including tmux 1.8 and 1.9 (RHEL/CentOS 7, Debian 8).
- **A vanished session is recreated** instead of the tab closing with "exit 1".
- **Flaky links still give up eventually**, and turning auto-reconnect off stops a countdown immediately.

### Fixes

- **The SFTP pane works again after a reconnect.**
- **The bundled X server (VcXsrv) closes properly** after a failed connect with X11 forwarding.
- **Exit codes are shown again**, e.g. "Disconnected (exit 1)".
- **A readable error** if you open more than 99 tabs of the same persistent session.

### Website

The site leads with persistent sessions and auto-reconnect, and the docs have a full guide under **Features → Persistent sessions & auto-reconnect** (#184).
